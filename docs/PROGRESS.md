## 결정 기록

### 2026-09-28 · 필드 지형별 움직임: 걷기 · 도끼 · 배

사용자가 도끼 시트(`cat-axe`)와 배 시트(`cat-boat`)를 줬다 (둘 다 1536×1024, 6열 4행).
정할 것 네 가지는 추천안대로 갔다: 풀밭도 걷기 · 배는 아무 물가에서나 · 숲은 연출만(도끼 획득 조건 없음) · 바다도 배로.

- **지형 마스크** `src/assets/field-terrain.png` — 필드 그림과 같은 크기, 흰색 걷기 · 초록 숲 · 파랑 물 · **검정 못 감**.
  `node tools/terrain.mjs` 가 필드 그림 색으로 초안을 만든다. 물은 거의 정확하고(다리·선착장은 땅으로 남는다),
  숲은 진한 초록이 주변 48px 안에 45% 넘게 모인 곳이라 들판의 나무 한두 그루로는 도끼 모드가 안 된다.
  흙길은 숲 한가운데라도 걷기. **검정은 초안에 없다** — 바위·집 위를 막고 싶으면 검정으로 칠하면 바로 막힌다.
  ⚠ 직접 고친 뒤 `tools/terrain.mjs` 를 다시 돌리면 덮어쓴다 (필드 그림을 바꿨을 때만 다시 돌린다).
  게임에서 T 키(또는 `?terrain`)로 겹쳐 볼 수 있다: 숲 분홍 · 물 하늘색 · 막힘 빨강.
- **물은 "다음 걸음"으로 판단** — 다음 걸음이 물이면 거기서 배에 오르고, 뱃머리(배 중심에서 고양이 키의 0.65배)가 뭍에 닿으면 내린다.
  그래서 물 위를 걷거나 땅 위에서 노 젓는 프레임이 없다 (`npm run check` 무작위 20초 + `npm run verify` 실측으로 확인).
- **숲은 0.15초 머물러야** 도끼로 바뀐다. 경계를 따라 걸어도 모션이 깜빡이지 않는다.
- **배 오르기**: 시트 첫 컷에서 고양이가 배 옆 (고양이 키의 1.17배)에 서 있어서, 배를 그만큼 앞 물 위에 띄운다 → 걷던 자리에서 그대로 뛰어든다.
  **내리기**: 배는 그 자리에 두고 뛰어내린다. 오른쪽 뭍이면 시트를 뒤집는다(시트는 왼쪽에 내려선다). 배는 물결과 함께 사라진다.
  오르내리는 0.6초 동안은 조작을 받지 않는다.
- **도끼**: 숲에서 걸으면 0.85초마다 한 번 휘두른다(0.45초, 그동안 거의 멈춤). 내려찍는 컷에 나뭇잎 파티클 + "탁".
  숲에서 속도 0.55배, 배 1.15배.
- **숲에서 발 앞을 가리는 수풀**: 배경이 그림 한 장이라 나무 뒤로 들어갈 수 없어서, 발밑의 배경 그림을 고양이 다리 위에
  가장자리를 부드럽게 다시 그린다. 같은 그림이라 따로 놀지 않는다.
- **소리**: 도끼 "탁", 배 타고 내릴 때 "첨벙", 노 저을 때마다 작은 "찰랑" (전부 Web Audio 합성).
- **필드 고양이 크기**: 사용자 요청으로 두 번 줄였다 — 75% (키 45.8 → 34px), 다시 50% (**17px**, `field.json` `catBody`).
  **크기를 바꿀 땐 `catBody` 한 값만 고친다.** 걷기·도끼·배 스프라이트, 그림자, 수풀, 배 간격(`modes.boat.offset`)·뱃머리(`bow`, 둘 다 고양이 키 배수),
  도끼로 친 지점, 나뭇잎·물보라·물결 크기와 속도가 전부 이 값에 비례한다. 걷는 속도는 지도 기준이라 크기와 따로 논다 — 50% 로 줄인 뒤 너무 빨라 보여서 30% 늦췄다 (170 → **119px/초**, `field.json` `speed`).
- **시트끼리 크기 맞추기**: 대기 행 키(`bodyH`)로 맞춘다. **배 시트만 예외** — 배를 크게 그리느라 고양이가 절반 크기라서,
  배 옆에 서 있는 컷(오르기 첫 컷·내리기 마지막 컷)의 키로 맞춘다. 대기 행으로 맞췄더니 내린 뒤 고양이가 두 배로 커졌다.
- 배는 오르내리는 동안 행 높이가 달라도(뛰는 고양이) 같은 크기로 그린다 (`rowScale` 1).
- 튜닝 값은 전부 `src/data/field.json`: `forestDelay` `boardTime` `modes.{walk,axe,boat}` (속도·도끼 주기·노 간격·배 offset·bow — offset·bow 는 고양이 키 배수).
- **스프라이트 시트 7장도 WebP 로** — Chrome 인코더는 알파를 무손실로 저장해서 칸 자르기 결과가 PNG 와 같다(알파 분포 동일,
  verify 6칸 통과). 시트 10.3MB → 2.75MB. **에셋 합계 3.3MB** (새 시트를 PNG 로 넣었으면 11.5MB 로 한도 초과였다).
  지형 마스크만 색이 정확해야 해서 PNG.

### 2026-09-28 · 바깥 필드와 워프

사용자가 준 필드 그림(`src/assets/field.webp`, 1672×941)으로 바깥 필드를 만들었다.

- **흐름**: 필드 항구 집 앞에서 시작 → 집 문 앞 워프에 0.8초 머물면 던전 → 던전 오른쪽 위 노란 매트(맵의 `E`)를
  밟으면 필드 집 앞으로. 목숨을 다 써 낮잠이 들면 R 로 집 앞에서 깨어난다 (GDD 1장 "마을에서 깨어난다").
- **필드 좌표는 배경 그림 픽셀 그대로.** 던전처럼 원근 매핑을 하지 않고 화면 방향으로 걷는다
  (세로는 비스듬한 시점만큼 0.72배). 2배 확대해 고양이를 따라가고, 그림 바깥은 안 보이게 카메라를 가둔다.
- **자유 이동**: 처음엔 그림 가장자리만 막았다. → 같은 날 지형 마스크를 붙였다 (위 "지형별 움직임" 참고).
- **워프는 임시 그래픽** (빛 원 + 빛 기둥 + 이름표, 머무는 동안 링이 찬다). 스프라이트 시트가 오면
  `src/field-draw.ts` 의 `drawWarp` 만 바꾸면 된다.
- **던전 입구 추가 방법**: `src/data/field.json` 의 `warps` 에 항목 하나 추가 — `at`(원 중심), `r`(반지름),
  `dwell`(머무는 초), `to`(방 id), `back`(던전에서 나왔을 때 서는 곳), `label`. 좌표는 필드 그림 픽셀.
- 워프 안에서 시작하면 한 번 나갔다 들어와야 작동한다 (도착하자마자 되돌아가지 않게).
- 장면 전환은 크림색 페이드 0.28초.
- 방 데이터(네 꼭짓점, 충돌 맵, 나가는 곳)를 코드에서 `src/data/rooms.json` 으로 옮겼다 (프로젝트 규칙).
- **배경 두 장을 WebP 로** (Chrome 내장 인코더, 품질 0.9): 필드 3.2MB → 460KB, 골목 1.6MB → 115KB. 에셋 합계 7.4MB.

### 2026-09-28 · 비주얼 전환: 3D 필드 → 2D 프리렌더 배경 ★

GDD 3장의 C안(3D 로우폴리 필드 + 빌보드 스프라이트, Three.js)을 버리고,
**방마다 렌더된 그림 한 장을 배경으로 깔고 그 위에 스프라이트를 올리는 2D**로 바꿨다. 사용자 결정.

- **이유**: 목업 그림(`src/assets/room-alley.webp`)의 퀄리티를 그대로 게임 화면으로 쓰고 싶어서.
  "3D 배경이 아니라 저 이미지를 배경으로 쓰는 캐주얼한 2D."
- **바뀐 것**
  - Three.js 제거 → Canvas 2D. 게임 코드 번들 547KB → 약 18KB.
  - 배경 그림이 **원근으로 렌더돼 있어** 위아래 타일 크기가 26% 다르다. 아이소메트릭 공식으로는
    안 맞아서, 바닥 네 꼭짓점을 찍어 원근 변환(호모그래피)으로 매핑한다 (`src/iso.ts` `CORNERS`).
  - 조명·그림자는 그림에 구워져 있다. 캐릭터는 발밑 블롭 섀도만.
- **영향 (앞으로 결정할 것)**
  - **방 하나당 배경 그림 한 장이 필요하다.** GDD 6장 절차적 생성은 "모듈을 조립"이 아니라
    "미리 그려 둔 방 중에 고르기"가 된다. 1층 10~14방이면 바이옴당 그 수만큼 그림이 필요.
  - GDD 3·10·11장(3D 모듈 킷, glTF, InstancedMesh, 노멀맵 스프라이트)은 현재 구현과 다르다.
  - 캐릭터가 배경의 화분 뒤로 가려지는 연출은 불가 (그림 한 장이라 앞뒤 레이어가 없다).

### 전투 감각

- **냥펀치 자동 조준**: 사거리(1.7m) 안 가장 가까운 쥐 쪽으로 돌려 친다. 조준이 없으면 바라보는 방향이
  마지막 이동 방향이라 멈춰서 때릴 때 헛쳤다.
- **근접 쥐는 고양이 화면 옆자리로 붙는다.** 위·아래로 붙으면 스프라이트가 겹쳐 몸을 가린다.
  여럿이면 양옆을 나눠 선다. 몸끼리는 쥐↔쥐 1.1m, 쥐↔고양이 1.0m 간격 (고양이는 안 밀린다).
- **쥐 공격 모션**: 공격 행 6칸 = 준비 3칸(예고 시간 동안) + 타격 3칸(0.24초) → 쿨다운엔 대기 자세.
- 쥐가 바라보는 방향은 화면 좌우 기준 (아이소메트릭에선 월드 x−z).

## 시트 슬라이서 (src/sheet.ts) — 시트를 바꿀 때 알아둘 것

1. 행: 가로 전체에 알파가 없는 줄로 나눈다.
2. 열: 행 안에서 알파가 없는 세로줄로 나눈다. **칼끝·주먹이 옆 칸에 닿으면 두 프레임이 붙어 한 칸이 된다**
   → 칸이 모자라면 가장 넓은 구간을 가운데 절반에서 알파가 가장 적은 열로 가른다.
3. 가로 기준점 = 프레임마다 **몸 무게중심**(전체 픽셀 x 의 중앙값). 공격 때 밀려나오지 않고, 돌아설 때 제자리.
4. 세로 기준점 = 행 단위 발바닥 중앙값 (프레임마다 재면 지면이 출렁인다).
5. 행 배율 = 행별 유효 높이로 정규화 (행마다 캐릭터 키가 최대 17% 다르다). 모션 전환 때 0.1초 보간.
6. 안전망: 없는 칸을 요청하면 마지막 칸을 그린다 (사라지지 않게).
7. 칸이 **많이** 잡히면: 점 노이즈(보통 조각의 15% 미만)는 버리고, 그래도 많으면 가장 가까운 조각끼리 합친다.
   배에서 내려 옆에 선 고양이처럼 한 프레임이 떨어진 두 조각일 수 있어서, 작은 조각을 그냥 버리면 안 된다.
8. 배 시트는 `anchor: 'hull'` — 바닥 40% 안 가장 긴 가로줄(선체) 가운데가 기준. 무게중심이면 고양이가 뛰어들 때 배가 미끄러진다.
9. 시트끼리 크기는 대기 행 키 `bodyH` 로 맞춘다 (배 시트 예외는 결정 기록 참고).

## 검증

- `npm run check` — 로직 자체 체크 8종 (필드 워프, 지형별 움직임 포함). 지형 체크는 가짜 지도에서
  물가 오르기·내리기·숲 도끼질·경계 깜빡임·막힌 곳을 보고, **무작위 20초 조작 중 매 프레임** 물 위를 걷거나 땅 위에서 배를 타지 않는지 본다.
- `npm run verify` — Chrome 을 띄워 10초 동안 실제로 돌린다. 모든 시트 행 6칸, 없는 칸 요청 0,
  반투명 프레임 0, 프레임 병합 0, 순간 점프 60px 이하를 검사하고 공격·피격 연속 촬영을 `tools/out/` 에 남긴다.
  그리고 **필드 ↔ 던전 왕복을 실제 키 입력으로 걷는다**: 필드 시작 → 워프까지 걸어가 머묾 → 던전 →
  노란 매트까지 걸어감 → 집 앞 복귀 → 다시 빨려 들어가지 않음.
  **필드 지형**도 실제 키로 걷는다: 선착장에서 바다로 → 배 → 뭍으로 → 내림 → 가장 가까운 숲 → 도끼질. 그동안 매 프레임 불변식을 감시하고,
  오르기·내리기·도끼질 연속 촬영을 `tools/out/field-*.png` 에 남긴다.
  마지막 결과(2026-09-28): 모두 통과. 최대 점프는 칼 쥐 돌아설 때 31px(꼬리가 반대편으로 넘어가는 폭).

## 남은 일

높은 순서대로.

1. **필드 던전 입구** — 사용자가 위치를 정해 준다. `field.json` 의 `warps` 에 추가, 방마다 `rooms.json` 항목과 배경 그림.
2. **워프 스프라이트 시트** — 사용자가 준비 중. 오면 `drawWarp` 를 시트 재생으로 교체.
3. **냥력 게이지 + 털뭉치·식빵 굽기·우다다** (GDD 5장) — 시트에 해당 애니메이션이 필요하다.
4. **장난감 5개** (M1 범위, GDD 7장) — 데이터는 `src/data/` JSON.
5. **무적 표시** — 깜빡임을 뺀 뒤 부활 무적(1.5초)이 안 보인다. 발밑 링 같은 다른 방식으로.
6. **치명타** (GDD 5% / 150%) — 데미지 숫자에 변화가 생긴다.
7. **지형 마스크 다듬기** — 초안이라 숲 경계가 거칠다. 바위·집 위를 막고 싶으면 검정으로 칠하면 된다 (코드는 이미 지원).
8. 방 여러 개 / 층 구조 — 방마다 배경 그림 + 네 꼭짓점 + 충돌 맵 (`rooms.json`). 지금 `iso.ts` 는 `alley` 고정.
9. 낚시 확장 자리 (`MiniGame`, `fishing_spot`, `rodRestore`·`fishDex`) — 저장(M2) 붙일 때 같이.
10. 8방향 스프라이트 — 지금은 좌우 반전만. 필드에서 위아래로 물에 들어가도 시트는 옆모습이다.
11. GitHub Actions 자동 배포 — `gh auth refresh -s workflow` 한 번 필요.
12. README — 좀 더 다듬은 뒤에 (사용자 요청으로 보류).
